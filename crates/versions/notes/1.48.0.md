# Rust 1.48.0（2020-11-19）

> 来源：[releases.rs/docs/1.48.0](https://releases.rs/docs/1.48.0/)；演示：`cargo run -p versions --bin rustc_1_48_0`

## Language
- **`unsafe` 关键字在模块上语法合法**——`unsafe mod foo {}` 现在能被解析（供过程宏使用），但语义检查仍会拒绝。

## Compiler
- 稳定 `-C link-self-contained=<yes|no>`：告诉 rustc 是否链接自带的 C 运行时/库（仅 windows-gnu、linux-musl、wasi 平台支持）。
- `-C target-feature=+crt-static` 现可用于 linux-gnu 目标（cargo 需显式传 `--target`）。
- 新增 tier 2* 目标：`aarch64-unknown-linux-musl`（* 平台分层的说明见官方 platform support 页）。

## Libraries
- `io::Write` 现在为 `&ChildStdin`、`&Sink`、`&Stdout`、`&Stderr` 实现。
- **任意长度的数组现在实现 `TryFrom<Vec<T>>`**（此前止步长度 32）。
- `matches!` 宏支持尾逗号。
- `Vec<A>` 实现 `PartialEq<[B]>`（`A: PartialEq<B>`）。
- `RefCell::{replace, replace_with, clone}` 现在带 `#[track_caller]`，panic 报告调用方位置。

## Stabilized APIs
- `slice::as_ptr_range` — 切片指针区间的 `Range<*const T>` 视图
- `slice::as_mut_ptr_range` — 可变版本
- `VecDeque::make_contiguous` — 把环形缓冲旋转成一段连续内存，返回 `&mut [T]`
- `future::pending` — 永不完成的 future
- `future::ready` — 立即以值完成的 future
- 以下既有方法成为 const fn：
  - `Option::{is_some, is_none, as_ref}`
  - `Result::{is_ok, is_err, as_ref}`
  - `Ordering::{reverse, then}`

## Cargo
- （本版无条目）

## Rustdoc
- **intra-doc link**：文档注释里直接用 `[`std::future`]` 这样的路径写法，rustdoc 自动生成指向对应项的链接。
- `#[doc(alias = "<alias>")]`：给项加搜索别名，rustdoc UI 搜索时可命中。

## Compatibility Notes
- const fn 内对 `'static` 引用的提升（promotion）规则改为与普通 fn 体一致：`&foo()` 在 const fn 中不再被提升为 `'static`。
- trait 对象上的关联类型绑定现在会校验是否满足 trait 声明的约束。
- 关联类型/opaque type 上的 trait 约束有歧义时，编译器不再任意挑选。
- 修复宏里递归 nonterminal 在 pretty-print/reparse 检查中的展开；写法不正确的宏可能开始报错。
- 非零大小类型的 `&mut` 引用不再被提升（promoted）。
- 在无效位置使用 `#[link_name]`、`#[cold]` 等属性现在会告警。
- 更新 `arch::{x86, x86_64}` 中 `_mm256_extract_epi8/_mm256_extract_epi16` 签名，返回 `i32` 以对齐厂商定义。
- `mem::uninitialized` 若结构体/枚举内部类型禁止零初始化，现在会 panic。
- `#[target_feature]` 用在无效位置现在会报错。
- 外来异常（foreign exceptions）现在会被 `catch_unwind` 捕获并导致 abort（仍属未定义行为，见 catch_unwind 文档）。

## Internal Only
- 从源码构建 rustc 默认改用 ninja（`ninja=false` 可继续用 make）。
- `cg_llvm: fewer_names in uncached_llvm_type`。
- `ensure_sufficient_stack()` 不再是泛型。
