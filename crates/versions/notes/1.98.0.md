# Rust 1.98.0（2026-08-20）

> 来源：[releases.rs/docs/1.98.0](https://releases.rs/docs/1.98.0/)；演示：`cargo run -p versions --bin rustc_1_98_0`

## Language
- unsize 强转时允许缩短 `&mut` 的生命周期（即使处于不变位置）：如 `Cell<&'long mut i32>` 可强转为 `Cell<&'short mut dyn Send>`（此前只在 &mut→& 或 &→& 时允许）。
- 新 `invalid_runtime_symbol_definitions`（deny）与 `suspicious_runtime_symbol_definitions`（warn）lint：针对 memcmp/memset/strlen 等核心运行时符号，后续版本将扩展范围。
- 新 `c_void_returns` lint（warn）：检查 `core::ffi::c_void` 作为返回类型。

## Platform Support
- 新 Tier 3：`powerpc64-unknown-linux-gnuelfv2`、`aarch64-unknown-linux-pauthtest`。
- thumbv7a/thumbv7r/thumbv8r 系列 5 个目标升 Tier 2。

## Libraries
- `Panic[Hook]Info` 中 `Location<'_>` 生命周期改为 `'static`。
- `RangeInclusive::from(legacy::RangeInclusive)` 补 panic 文档；`ManuallyDrop` 与 Box 的交互已修复（补文档）。
- 稳定 LoongArch CRC intrinsics。
- **derive 宏现在显式稳定于 `{core,std}::derive`**：1.96 曾意外稳定，本版明确接受为稳定 API；MSRV 按 1.96 计。

## Stabilized APIs（全列）
- `str::substr_range`
- `[T]::subslice_range`
- `core::fmt::NumBuffer<{integer}>::format_into`
- `Send/Sync for std::process::CommandArgs`
- `{fN}::algebraic_{add, sub, mul, div, rem}`（5 个）
- `NonZero<{integer}>::from_str_radix`
- `String::{from_utf16le, from_utf16le_lossy, from_utf16be, from_utf16be_lossy}`
- **`[T]::strip_circumfix`、`str::strip_circumfix`**（去掉成对环绕符号，如括号/引号）
- **`Atomic<T>::from_mut`、`Atomic<T>::get_mut_slice`、`Atomic<T>::from_mut_slice`**（泛型原子：引用转 Atomic 视图）
- `std::range::legacy`（旧 range 的过渡模块）

## Compatibility Notes（全列）
- trait object 类型完全省略生命周期 bound 的极特定场景可能解析不同甚至被拒。
- 更多歧义 import 报错；`ambiguous_glob_imports` 部分场景升为硬错误。
- Windows 线程局部变量析构改用 Fiber Local Storage (FLS)。
- `Type = Type` / `Type == Type` 形式的 where bound 不再允许（语法层面）。
- 确保 `std::env::Vars{,Os}` 不实现 Send/Sync。
- 部分属性的参数未正确拒绝的问题修复。
- **`repr(transparent)` 对"可忽略的 trivial 布局字段"更严格**：repr(C) 类型、含私有字段类型、`#[non_exhaustive]` 类型不再算 trivial。
- 涉及 repr 属性时 `transmute()` 的"大小相等"检查更正确。
- 打印字符串/char 时转义更多字符。
- `derive(PartialOrd)` 在 `derive(Ord)` 时用快速路径 —— PartialOrd 与 Ord 不一致的手写 impl 可能出问题。
- `assert_eq!`/`assert_ne!` 增加临时作用域。
- 堵上模式匹配结构相等检查的漏洞：常量匹配与手写 PartialEq 不一致 + derive(PartialEq) 存在的场景。
- Emscripten 无条件使用 WASM 异常处理 ABI（移除 `-Zemscripten-wasm-eh=false` 回退开关）。
- UNSAFE_CODE lint 对所有 unsafe 属性一致发出。
- Solaris：移除 `File::lock` 实现（语义错误，返回 "unsupported"）。
- windows-gnu 目标指定 baseline tools 版本；rustfmt 会发现 `cfg_select!` 中定义的模块文件（格式化范围扩大）。
