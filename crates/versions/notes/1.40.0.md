# Rust 1.40.0（2019-12-19）

> 来源：[releases.rs/docs/1.40.0](https://releases.rs/docs/1.40.0/)；演示：`cargo run -p versions --bin rustc_1_40_0`

## Language
- **tuple struct/枚举 tuple 变体的构造函数可用于 const 上下文**（如 `const ORIGIN: Point = { let c = Point; c(0, 0) };`）。
- **`#[non_exhaustive]` 稳定**（RFC 2008）：struct/enum/枚举变体可声明"未来还会加字段/变体"，外部 crate match 必须带通配分支。
- 函数式过程宏可以在 extern 块和类型位置使用（`type Generated = macro!();`）。
- 函数式/attribute过程宏可展开出 `macro_rules!` 条目（宏生成宏）。
- `macro_rules!` 的 meta 匹配器支持现代属性语法（`#[$m:meta]` 也能匹配 `#[attr(tokens)]`）。

## Compiler
- 新增 tier 3 目标：thumbv7neon-unknown-linux-musleabihf、aarch64-unknown-none-softfloat、mips64(el)-unknown-linux-muslabi64。

## Libraries
- 无符号数字类型的 `is_power_of_two` 成为 const fn。

## Stabilized APIs
- `BTreeMap::get_key_value` — 按 key 同时取 key/value
- `HashMap::get_key_value` — 同上（HashMap 版）
- `Option::as_deref_mut` — `Option<&mut T>` → `Option<&mut T::Target>`
- `Option::as_deref` — `Option<&T>` → `Option<&T::Target>`
- `Option::flatten` — `Option<Option<T>>` → `Option<T>`
- `UdpSocket::peer_addr` — 对端地址
- `f32::to_be_bytes` / `to_le_bytes` / `to_ne_bytes` — 编码为字节
- `f64::to_be_bytes` / `to_le_bytes` / `to_ne_bytes` — 同上（f64）
- `f32::from_be_bytes` / `from_le_bytes` / `from_ne_bytes` — 字节→浮点
- `f64::from_be_bytes` / `from_le_bytes` / `from_ne_bytes` — 同上（f64）
- `mem::take` — 替换出值并留下 `T::default()`（`std::mem::replace(t, T::default())`）
- `slice::repeat` — 切片重复 N 次
- `todo!` — 标记未实现的语义化 `unimplemented!()`

## Cargo
- Cargo 现在总是显示警告（而非只在 fresh build 时）。
- 虚拟 workspace 传入 feature 旗标（除 `--all-features`）报错。
- 可发布无版本的 dev-dependencies。

## Misc
- `#[cfg(doctest)]`：仅运行 doctest 时编译对应条目。

## Compatibility Notes
- 2015 edition 的 NLL 警告现成为硬错误。
- `include!` 无法包含整个文件时警告（此前只包含第一个表达式）。
- 函数原型和 const 上的 `#[inline]` 在 `unused_attribute` 下发出警告；trait/extern 块内其他位置使用 `#[inline]` 成为硬错误。
