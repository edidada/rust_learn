# Rust 1.81.0（2024-09-05）

> 来源：[releases.rs/docs/1.81.0](https://releases.rs/docs/1.81.0/)；演示：`cargo run -p versions --bin rustc_1_81_0`

## Language
- `extern "C"` 函数中未捕获的 panic 现在直接 abort。
- 修复省略 self 生命周期中多个 `&` 的歧义情形。
- **稳定 `#[expect]`（RFC 2383）**：与 `#[allow]` 相反——若被"预期"的 lint 实际没有发生，反而得到一个 `unfulfilled_lint_expectations` 警告；预期被满足时静默。用于确保某段代码将来一旦修复即可被发现（例如占位的死代码）。
- 方法解析改为约束隐藏类型而非直接拒绝候选。
- `elided_lifetimes_in_associated_constant` 升为 deny。
- `offset_from` 总是允许指向同一地址的指针。
- trait 系统允许在子类型化/非定长转型中约束 opaque 类型。
- 关键字生命周期在展开前 deny。

## Compiler
- 指针转 trait 对象的 cast 更严格；transmute 大小检查考虑对齐；移除 `box_pointers` lint。
- 新目标：Xtensa 系列、i686-unknown-redox（tier 3）；arm64ec-pc-windows-msvc 升 tier 2；wasm32-wasi 无条件警告（见兼容性）。

## Libraries
- **拆分 core 的 `PanicInfo` 与 std 的 `PanicInfo`**：std 侧改名 `PanicHookInfo`（panic hook 的参数），core 侧保持 `PanicInfo`（`#[panic_handler]` 的参数）。
- `{Rc,Arc}::make_mut()` 泛化到不定长类型；**排序实现更换**：稳定 `driftsort`、非稳定 `ipnsort`（`slice::sort*`/`select_nth*` 大幅提速；要求 `Ord` 实现全序，违者 panic）。
- 修复 Command 批处理文件参数转义漏洞（CVE-2024-43402）。

## Stabilized APIs
- `core::error`（no_std 也可用 `Error` trait）
- `hint::assert_unchecked`
- `fs::exists`
- `AtomicBool::fetch_not`
- `Duration::abs_diff`
- `IoSlice::advance` / `IoSlice::advance_slices` / `IoSliceMut::advance` / `IoSliceMut::advance_slices`
- `PanicHookInfo`（std panic hook 参数的新名字）/ `PanicInfo::message`（core）/ `PanicMessage` trait
- 以下可用于 const 上下文：`char::from_u32_unchecked`（函数与方法）、`CStr::count_bytes`、`CStr::from_ptr`

## Cargo
- `.cargo_vcs_info.json` 总是包含（即使 `--allow-dirty`）；打包时禁止指向不存在文件的 `license-file`/`readme`；禁止 `--release/--debug` 与 `--profile` 同时使用；移除 `lib.plugin` 键。

## Compatibility Notes
- `wasm32-wasi` 目标编译告警（改用 `wasm32-wasip1`，同名，计划 2025-01 移除旧名）。
- `std::panic::PanicInfo` 改名 `PanicHookInfo`（1.82 起旧名弃用告警）；`core::panic::PanicInfo` 不变（类型职责不同）。
- 新排序实现可能对违反全序的 `Ord` 实现直接 panic（旧实现"不检查"）。
- 极少数情况下 trait solver 内部求值顺序变化可能产生新的 fatal overflow 错误。
