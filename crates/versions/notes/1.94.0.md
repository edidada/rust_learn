# Rust 1.94.0（2026-03-05）

> 来源：[releases.rs/docs/1.94.0](https://releases.rs/docs/1.94.0/)；演示：`cargo run -p versions --bin rustc_1_94_0`

## Language
- impl/impl item 继承对应 trait 与 trait item 的 `dead_code` lint 级别。
- 稳定 29 个额外 RISC-V target features（大部分覆盖 RVA22U64/RVA23U64 profile）。
- `unused_visibilities` lint（warn）扩展到 `const _` 声明上的可见性。
- Unicode 数据升到 17；闭包生命周期错误更少（误报修复）。

## Platform Support
- 新 Tier 3 目标 `riscv64im-unknown-none-elf`。

## Libraries
- 放宽部分 `BinaryHeap<T>` 方法的 `T: Ord` bound。

## Stabilized APIs
- `<[T]>::array_windows`
- `<[T]>::element_offset`
- **`LazyCell::{get, get_mut, force_mut}`、`LazyLock::{get, get_mut, force_mut}`**
- `impl TryFrom<char> for usize`
- `Peekable::next_if_map` / `Peekable::next_if_map_mut`
- x86 avx512fp16 intrinsics、AArch64 NEON fp16 intrinsics（不含依赖 unstable `f16` 的那些）
- `f32/f64::consts::{EULER_GAMMA, GOLDEN_RATIO}`（4 项）
- const 化（此前已稳定）：`f32/f64::mul_add`

## Cargo
- 稳定顶层 `include` 配置键（加载额外配置文件，便于组织/共享）。
- registry index 稳定 `pubtime` 字段（记录发布时间，未来支撑基于时间的依赖解析；crates.io 会逐步回填）。
- 解析 TOML v1.1 清单与配置（在 Cargo.toml 用 v1.1 特性会抬高开发 MSRV，发布仍兼容旧解析器）。
- `CARGO_BIN_EXE_<crate>` 在运行期可用。

## Compatibility Notes（多，全列）
- 禁止自由"转换" dyn 类型的生命周期 bound。
- 模式匹配下闭包捕获行为修正：可能由"整变量 move"变成"部分 move + 部分借用"，borrow checker 可能新报错、Drop 时点可能变化。
- **std 宏经由 prelude 导入而不是注入 `#[macro_use]`** → 同名 glob 导入将产生歧义错误（如 crate 自定义 `matches!` + glob import 需显式指定）；例外：`core::panic` / `std::panic` 歧义时发新警告 `ambiguous_panic_imports`（`#![no_std]` glob 引 std 亦可能触发）。
- 表达式位置 `include!(…)` 不再剥 shebang（含 shebang 的被包含文件将编译失败）。
- 歧义 glob reexport 跨 crate 可见（本地/跨 crate 行为统一，可能出现新歧义错误）。
- 检查 well-formedness 前不再规整 where 子句。
- 对无函数体的 trait 方法上的 codegen 属性引入 future-compat 警告（当前无效果）。
- Windows 上 `SystemTime::checked_sub_duration` 对早于 Windows epoch（1/1/1601）的时间返回 None。
- 生命周期标识符（如 `'a`）现在做 NFC 规范化。
- 交叉编译文件名处理大改：编译器输出路径始终保持原始相对性/`--remap-path-prefix`；副作用是 path 依赖/工作区成员的诊断路径变为相对路径。

## Internal
