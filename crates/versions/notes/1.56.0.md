# Rust 1.56.0（2021-10-21）

> 来源：[releases.rs/docs/1.56.0](https://releases.rs/docs/1.56.0/)；演示：`cargo run -p versions --bin rustc_1_56_0`

## Language
- **Edition 2021 稳定**。主要行为差异：
  - **闭包分离捕获（disjoint capture）**：闭包只捕获它实际用到的字段，而不是整个结构体，减少借用冲突。
  - **`IntoIterator for [T; N]` 落地**：`arr.into_iter()` 方法调用在 2021 edition 下按值迭代（`Item = T`），终结了 1.53 时"方法调用借迭代"的历史语义（数组上的 `.into_iter()` 不再有歧义警告）。
  - **panic 宏一致性**：`panic!("非格式串参数")` 不再接受单个非字符串参数；需 `panic!("{}", x)` 或 `panic_any(x)`；`panic!("{ident}")` 捕获要等 1.58。
  - **`:pat` 宏匹配器语义变化**：在 macro_rules! 中匹配完整模式（含 or-patterns 等新语义），旧用 `:pat` 依赖 top-or 的代码需要迁移（配 1.53 加的 `:pat_param`）。

## Compiler
- 升级 LLVM 13。
- aarch64-unknown-freebsd 支持 memory/address/thread sanitizer。
- 所有 iOS 目标可统一指定 deployment target。
- `--force-warn` 强制打开告警（主要为 cargo fix 使用）。
- 提升 `aarch64-apple-ios-sim` 到 Tier 2*；新增 tier 3 `powerpc-unknown-freebsd`、`riscv32imc-esp-espidf`。

## Libraries
- 允许 Windows 上经 stdout/stderr 写不完整 UTF-8 序列（跨多次 write 拼接字符）。
- `Instant` 防回滑改用 `AtomicU{64,128}` 替代 `Mutex`（争用下表现更好）。
- `(Extend<A>, Extend<B>)` 实现 `Extend<(A, B)>`。
- `std::io::Sink` / `std::io::Empty` 实现 `Default`、`Copy`、`Clone`。
- 所有集合实现 `From<[(K, V); N]>`。
- `Pin` 的 `impl Future` 移除 `P: Unpin` bound。
- 环境变量名含内部 null 或 `=` 时按"不存在"处理（此前 panic）。

## Stabilised APIs
- `std::os::unix::fs::chroot`
- `UnsafeCell::raw_get`
- `BufWriter::into_parts` — 拆出 writer 与错误
- `core::panic::{UnwindSafe, RefUnwindSafe, AssertUnwindSafe}` — 从 std 复制到 core
- `Vec::shrink_to` / `String::shrink_to` / `OsString::shrink_to` / `PathBuf::shrink_to` / `BinaryHeap::shrink_to` / `VecDeque::shrink_to` / `HashMap::shrink_to` / `HashSet::shrink_to`
- 以下 API 可用于 const 上下文：`std::mem::transmute`、`[T]::first`、`[T]::split_first`、`[T]::last`、`[T]::split_last`

## Cargo
- Cargo.toml 支持声明最小支持的 Rust 版本（`rust-version` 字段）；目前不影响依赖选择，但鼓励 CI 把它纳入测试矩阵。

## Compatibility notes
- Windows 命令行参数解析规则更新到 2008 后的最新规则（对齐 C/C++）。
- aarch64 上禁用 `aapcs` 调用约定（本来 LLVM 就不支持），提供更清晰的错误。
- `SEMICOLON_IN_EXPRESSIONS_FROM_MACROS` 默认 warn。
- escaped newline 跳过多行时告警。
- glibc ≤ 2.24 上 `Command::pre_exec` 内的 `libc::getpid`/`std::process::id` 可能返回不同值（直接使用 clone3 syscall，绕过 glibc 的 getpid 缓存）。
